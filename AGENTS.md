## Project Overview

cf-starter is a template for full-stack TypeScript apps on a single Cloudflare
Worker: a React SPA served as static assets, plus a Hono API under `/api`. It
ships a hello-world (`GET /api/health` and a page that calls it) so the whole
pipeline — tests, preview deploys, E2E, releases — is proven before any app
code exists.

There is no data layer by default. Add one per project from `docs/recipes/`.

---

## Stack

| Layer | Technology |
|---|---|
| Frontend | React 19, TypeScript, Vite 8, TanStack Router (file-based) |
| Client cache/state | TanStack Query v5 |
| Backend | Hono 4 on Cloudflare Workers |
| Styling | CSS Modules + design tokens in `src/react-app/index.css` |
| Package manager | Bun (pinned via mise) |
| Linter / Formatter | Biome |
| Testing | Vitest (unit, happy-dom), `@cloudflare/vitest-pool-workers` (integration), Playwright (E2E), React Testing Library, MSW |
| Commits | cz-git/czg + commitlint (gitmoji + conventional commits), Husky |
| Releases | semantic-release + semantic-release-gitmoji (semver, tagged `v{version}`) |
| CI/CD | GitHub Actions (`.github/workflows/`) |
| Tool/task management | mise (`mise.toml` wraps every `bun run` script as a `mise run` task) |

## Local Development Setup

```bash
mise install    # provisions the bun version pinned in mise.toml

# Activate mise so bun resolves in this shell (husky hooks run
# `bun run lint-staged` / `bun run test --run` and fail with "command not
# found" otherwise). Run once per session:
eval "$(mise activate)"

# Fallback for any single command when activation isn't in effect:
#   mise exec -- <cmd>

bun install
cp .dev.vars.example .dev.vars
bun run dev
```

Dev server: `http://localhost:5173` (Vite + the Worker via
`@cloudflare/vite-plugin`).

## Common Commands

```bash
bun run test --run        # unit/component tests once
bun run test:integration  # worker integration tests in workerd
bun run coverage          # unit tests with V8 coverage + thresholds
bun run test:e2e          # Playwright against the local dev server

bun run check:code        # biome check --write (lint + format + imports)
bun run typecheck         # tsc -b across all tsconfig projects
bun run check             # build + wrangler deploy --dry-run
bun run cf-typegen        # regenerate worker-configuration.d.ts

bun run commit            # interactive gitmoji commit prompt
```

Every command also has a `mise run <task>` alias in `mise.toml`
(e.g. `mise run test:run`, `mise run ci:local`).

and `vitest.config.integration.ts` — keep all four in sync.

## Commit Conventions

All commits **must** follow the gitmoji + conventional commits format,
enforced by commitlint and cz-git. Headers are capped at 100 characters.

```text
✨ feat(api): add rate limiting to the health route
🐛 fix(router): keep search params on redirect
♻️ refactor(hooks): extract useHealthQuery
📝 docs: update AGENTS.md
```

Do **not** bypass hooks with `--no-verify` unless documented.

### Branch naming

`<git-commit-type>/<issue-id>-<kebab-case-brief-description>` (e.g.
`fix/12-health-timeout`). Omit the issue id when there is none (e.g.
`docs/agents-mise-activation`). The commit prompt pre-fills type and issue from
the branch name.

## Testing

Three tiers:

1. **Unit / component** — `*.spec.ts(x)` co-located with source, run by Vitest
   (`vite.config.ts`) in happy-dom. Worker specs opt into
   `// @vitest-environment node` and drive Hono via `app.request()`. A global
   MSW server fails any unmocked request.
2. **Worker integration** — `*.integration.spec.ts`, run via
   `vitest.config.integration.ts` inside workerd. Requests go through the real
   entry point with `exports.default.fetch()` from `cloudflare:workers`.
3. **E2E** — Playwright specs in `e2e/`. Locally they start `bun run dev`; in
   CI they run against the PR's preview deployment (`BASE_URL`), in Chromium
   and Firefox.

Coverage is unit-only (V8 coverage is incompatible with workerd). Thresholds
live in `vite.config.ts`.

## Environments & Deployment

| Environment | Trigger | Wrangler env | Worker name |
|---|---|---|---|
| Production | Push to `main` | _(default)_ | `cf-starter` |
| Preview | Pull request | `preview` | `cf-starter-preview-pr-<n>` |

`.github/workflows/deploy.yml` builds (with `CLOUDFLARE_ENV=preview` on PRs so
the Vite plugin flattens `env.preview` into the build output), deploys, and
reports a GitHub Deployment. For non-fork PRs an `e2e` job then runs the
Playwright suite against the preview URL. `preview-cleanup.yml` deletes the
preview Worker when the PR closes.

GitHub Actions configuration:

| Name | Kind | Used by |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | Secret | deploy, preview-cleanup |
| `CLOUDFLARE_ACCOUNT_ID` | Secret | deploy, preview-cleanup |
| `RELEASE_APP_CLIENT_ID` | Variable | release |
| `RELEASE_APP_PRIVATE_KEY` | Secret | release |

Releases: semantic-release derives the bump from gitmoji (`:boom:` → major,
`:sparkles:` → minor, `:bug:` `:ambulance:` `:lock:` `:lipstick:` `:zap:`
`:recycle:` → patch), tags `v{version}`, and commits the `package.json` bump
via the release GitHub App.

## What to Avoid

- Do not use `npm`, `yarn`, or `pnpm` — Bun only.
- Do not add ESLint or Prettier — Biome handles both.
- Do not hand-edit `worker-configuration.d.ts` or `routeTree.gen.ts`.
- Do not declare a binding only at the top level of `wrangler.jsonc` — repeat
  it in `env.preview`, or previews break.
- Do not hardcode environment-specific values; use Wrangler `vars`, secrets,
  and bindings.
- Do not bypass commit hooks without a documented reason.
- Do not write refactor or feature plans into `docs/` — in-flight plans belong
  in GitHub issues. `docs/` is for decisions and reference material that
  outlive the work.
- Do not add inline `<script>`/`<style>` blocks to `index.html` — the CSP in
  `public/_headers` blocks them. A new third-party origin needs a deliberate
  CSP change.
- Do not use inline `style={}` props — styling goes in co-located CSS Modules.
